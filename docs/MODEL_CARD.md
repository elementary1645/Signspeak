# SignSpeak live recognizer: model card

**Intended use.** A hackathon prototype that recognises a small, human-verified set of
Indian Sign Language (ISL) signs from webcam landmarks and shows their meaning in English,
Kannada, Hindi or Tamil. It is not a translator, and it must not be used for medical,
emergency or legal communication.

**Inputs.** Browser MediaPipe hand (up to 2) and upper-body pose landmarks (lm-v1).
No images. New collection uses hp-v2-8fps: 16 actual frames at nominal 8 FPS over about
2 seconds. The original hp-v1 representation remains available: a 24-frame 15 FPS grid
over about 1.6 seconds. Models declare one feature/capture version and cannot be
interchanged. See `docs/data_schema.md` and `docs/PHASE3_LOWER_FPS_PROTOCOL.md`.

**Model.** A CPU scikit-learn classifier, chosen from RandomForest, ExtraTrees,
LogisticRegression and RBF-SVM by grouped out-of-fold macro-F1. A reserved NONE class
(rest, idle, transitions, random movement) is trained with the signs. A prediction is
shown only if NONE does not win and confidence and margin pass thresholds tuned on
validation folds.

**Data.** Only takes recorded on `/collect` by consenting, pseudonymous signers, for signs
a human verified against an exact official ISLRTC reference. No external dataset is used.

**Known limitations.**
- No face landmarks, so signs that need facial grammar or mouthing are excluded.
- A small vocabulary with few signers: expect errors with new people, lighting, cameras
  and backgrounds. Any unfamiliar movement can still be confidently misread as a sign.
- The trainer measures unseen-signer accuracy only with at least 3 signers
  (leave-one-signer-out). With 2 signers it groups folds by take (or by
  signer/session once there are 3 or more sessions), so the same people are in train and
  test and its numbers overstate accuracy for new people. For training run #1 a separate
  2-fold leave-one-signer-out check was run; see the section after the trainer's block.
- The kn/hi/ta meanings were drafted by an AI assistant and need native-speaker checks.

**Data.** 96 takes from **2 signers** (signer01, signer02), one session each
(`s20261104`). All takes are hp-v2-8fps-timed-1 and hand-evidence-v3: 16 frames at a
measured 7.7–8.4 FPS, none low_fps. Per signer: HELLO 8, THANK_YOU 8, YES 8, NO 8 and NONE
16 (2 of each of the 8 NONE prompts). Each take yields exactly one 16-frame window, so there
are 96 windows and 8 (or 16 for NONE) test windows per class per fold. One window is 12.5
percentage points of a sign's recall.

**Method.** This was run outside the trainer, reusing its own functions (`build_windows`,
the candidates, `tune`, `decide`). There are two folds: train on one signer, test on the
other. Within each fold the algorithm and the thresholds are chosen using **only the
training signer**: 5-fold inner CV grouped by take, the trainer's closed-set macro-F1
selection among latency-eligible models (logistic regression, RBF-SVM; random forest
19.5 ms and extra trees 20.7 ms exceed the 10 ms limit), and `tune` on those inner
out-of-fold predictions. The held-out signer is used only for scoring. Values are exact
fractions, or decimals truncated (not rounded).

By fold: signer02 → signer01 put 6 NONE windows as HELLO and 4 as YES, plus 1 HELLO → NONE
and 1 NO → YES. signer01 → signer02 put 4 HELLO windows as NONE and 1 as NO, plus 1 YES →
NONE.

**What this shows.**
- **HELLO ↔ NONE is the main confusion**, in both directions. NONE → YES is second.
  THANK_YOU was never confused. NO had a single error in each direction.
- **The two directions fail differently.** Trained on signer02, the model accepts most of
  signer01's non-signs as signs (NONE false-accept 0.625). Trained on signer01, it accepts
  no non-signs but misses 5 of signer02's 8 HELLO windows. Macro-F1 differs by 0.08.
- **Nothing here is stable.** The selected algorithm differs between folds, the tuned
  thresholds differ (0.4/0.0 versus 0.6/0.35), and each test cell holds 8 or 16 windows.
  With 2 signers this is two data points, not an estimate of accuracy for new people.
- **The trainer's own numbers above** (open-set macro-F1 0.972, NONE false-accept 6.25%)
  come from grouped-by-take folds with both signers in training. They are much better than
  any leave-one-signer-out result here and should not be quoted as accuracy.
- **Deployed bundle:** logistic regression trained on both signers. Its thresholds
  (min_confidence 0.8, min_margin 0.5) were grid-searched on the trainer's grouped-by-take
  out-of-fold predictions, maximising open-set macro-F1 with ties going to the stricter
  setting. They were never checked on an unseen signer. For reference only: logistic
  regression with exactly those thresholds, trained on signer01 and scored on signer02
  (the thresholds happen to be what that fold's own inner tuning picked for it), reached
  open-set macro-F1 0.6131 against 0.9163 without rejection. Strict thresholds may reject
  many correct signs from new people.
- **Held-out-sign check** (trainer, grouped by take): when YES was left out of training, 3
  of 16 YES windows (0.1875) were still accepted as another sign.

**Required before claiming accuracy:** at least 3 signers so that the trainer's
leave-one-signer-out runs. A second session from an existing signer adds variation but no
new-signer evidence.
